# ADR: Статический анализ кода, правила .editorconfig и .gitattributes

- Статус: Принято
- Дата: 2026-06-18
- Контекст: монорепозиторий DotnetVue3TemplateRu, backend на .NET 10; качество и единообразие C#-кода держатся на дисциплине и базовом форматировании

## Контекст

Корневой `.editorconfig` задаёт только базовое форматирование: отступы, кодировку, концы строк (LF), финальный перевод строки - без правил стиля C# (var, квалификация `this.`, expression-bodied, file-scoped namespaces и т.п.) и статических анализаторов. Без них классы дефектов и стилевые расхождения ловятся только на ревью или не ловятся вовсе. Отсюда задача: подключить Roslyn-анализаторы и расширить `.editorconfig` правилами стиля, оставив warnings-as-errors на будущий CI-гейт.

Без `.gitattributes` нормализация концов строк зависит от локальной настройки `core.autocrlf` каждого разработчика: git хранит LF, но в рабочее дерево на Windows разворачивает CRLF. У разработчика с другим `autocrlf` это даёт "ложные" изменения целых файлов в diff из-за смены CRLF<->LF.

Ограничения: уважать "Simplicity First" (не тащить набор анализаторов "на будущее"); не ломать сборку разовым включением строгих правил; backend пока маленький (~30 файлов), поэтому разовая чистка предупреждений дёшева именно сейчас.

## Решение

**Встроенные .NET-анализаторы + SonarAnalyzer.CSharp, правила стиля C# в `.editorconfig` на уровне warning, нормализация EOL через `.gitattributes`.**

- Анализаторы включены в [Directory.Build.props](../../Directory.Build.props) для всех .NET-проектов сразу: `EnableNetAnalyzers`, `AnalysisLevel=latest`, `AnalysisMode=Default`, `EnforceCodeStyleInBuild=true`. Пакет `SonarAnalyzer.CSharp` подключён глобальной `PackageReference` с `PrivateAssets=all` (не утекает потребителям пакетов); версия - в Central Package Management ([Directory.Packages.props](../../Directory.Packages.props)).
- Правила стиля C# в [.editorconfig](../../.editorconfig) взяты за основу из эталонного набора и адаптированы: все стилевые предпочтения заданы на уровне `warning`/`suggestion`, не `error`. Это принципиально - `severity = error` в `.editorconfig` становится ошибкой компиляции независимо от `TreatWarningsAsErrors`, что валило бы сборку. Шумные правила `CA*`/`IDE*`/`S*` погашены (`severity = none`) точечным списком.
- `TreatWarningsAsErrors` НЕ включаем: анализаторы дают предупреждения, сборка остаётся зелёной. Жёсткий gate появится вместе с CI-as-code (отдельный пункт shortlist).
- [.gitattributes](../../.gitattributes) задаёт `* text=auto eol=lf` - git нормализует текстовые файлы к LF и в репозитории, и в рабочем дереве, одинаково на всех машинах независимо от `autocrlf`. Это согласуется с `end_of_line = lf` в `.editorconfig` и снимает текущее расхождение (хранится LF, разворачивается CRLF). Бинарные файлы помечены `binary`, Windows-скрипты (`.bat`/`.cmd`) - `eol=crlf`.

## Почему не альтернативы

**Roslynator / Meziantou.Analyzer** вместо или вместе с Sonar. Шире покрытие, но и больше шума и разовой чистки. Начинаем со связки "встроенные CA + Sonar" (Sonar даёт качественный набор правил из коробки); Roslynator/Meziantou можно добавить позже, если потребуется.

**Стилевые правила как `:error` (как в исходном эталонном конфиге).** Дало бы строгий гейт, но `:error` в `.editorconfig` ломает сборку даже без `TreatWarningsAsErrors`, а CI-as-code ещё нет. Понизили до `warning`: правила видны, сборка не падает.

**Включить `TreatWarningsAsErrors` сразу.** Жёстко, но без CI заблокировало бы локальную разработку на каждом предупреждении при ещё не вычищенной кодовой базе. Откладываем до появления CI-пайплайна.

**Полагаться на `core.autocrlf` вместо `.gitattributes`.** Поведение тогда зависит от настройки каждой машины и даёт "ложные" CRLF/LF-диффы. `.gitattributes` фиксирует нормализацию как свойство репозитория.

## Плюсы

- Классы дефектов и стилевые расхождения ловятся анализаторами до ревью, единообразно во всех проектах (одна настройка в `Directory.Build.props`).
- Сборка остаётся зелёной: стиль на уровне warning, warnings-as-errors отключён - плавное внедрение без блокировки.
- Концы строк детерминированы и одинаковы на всех машинах; уходят "ложные" CRLF/LF-диффы.
- Версия анализатора - в одном месте (CPM), как и остальные пакеты.

## Минусы

- Ещё одна зависимость (`SonarAnalyzer.CSharp`) и заметный список подавлений в `.editorconfig`, который нужно поддерживать.
- Появляются предупреждения сборки, пока кодовая база не вычищена; без gate их легко игнорировать.
- Внедрение `.gitattributes` требует разовой ренормализации уже отслеженных файлов (`git add --renormalize .`) отдельным коммитом.

## Последствия

- При сборке (`dotnet build`) появляются новые предупреждения от анализаторов и стиля; их чистка - постепенная задача.
- Жёсткий gate (warnings-as-errors) включается позже вместе с CI-as-code; тогда же логично прогнать чистку предупреждений.
- Новые правила-исключения добавляются в `.editorconfig` точечно (`dotnet_diagnostic.<code>.severity`).
- Ренормализация концов строк - разовая операция; после неё рабочее дерево и репозиторий едины на LF.
