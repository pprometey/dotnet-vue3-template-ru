# ADR: Базовая доступность фронтенда (a11y)

- Статус: Принято
- Дата: 2026-06-19
- Контекст: монорепозиторий DotnetVue3TemplateRu, фронтенд - самостоятельное SPA на Vue 3 (ADR-0027); Storybook на моках MSW (ADR-0033); линт - ESLint flat config с `eslint-plugin-vue`

## Контекст

Интерфейсом пользуются самые разные люди, а не узкая группа обученных операторов, поэтому он нуждается в базовой проверке доступности (a11y). Очевидные дефекты - изображение без `alt`, поле формы без связанной метки, интерактивный элемент без поддержки клавиатуры, некорректный `role`/`aria` - легко пропустить при верстке и поймать только постфактум.

Нужен дешёвый базовый контроль, который не требует ни отдельного процесса тестирования, ни массового переписывания компонентов, и встраивается в уже существующие инструменты (Storybook и ESLint).

## Решение

**Базовый a11y в двух точках контроля: панель доступности в Storybook (`@storybook/addon-a11y`) и статические правила линта (`eslint-plugin-vuejs-accessibility`, набор `flat/recommended`).**

- **Storybook addon.** `@storybook/addon-a11y` подключён в `apps/frontend/web/.storybook/main.ts` (`addons: ["@storybook/addon-a11y"]`). Addon прогоняет axe-core по отрендеренной истории и показывает нарушения на отдельной вкладке "Accessibility". Это динамическая проверка реального DOM (контраст, ARIA, имена элементов), которую статический линт не видит. Версия addon выровнена с семейством Storybook (10.4.x).
- **ESLint plugin.** `eslint-plugin-vuejs-accessibility` подключён в корневом `eslint.config.mjs` через `...pluginVueA11y.configs["flat/recommended"]`, сразу после базового набора `eslint-plugin-vue`. Это статическая проверка шаблонов `.vue` (alt-text, form-control-has-label, aria-props, click-events-have-key-events и т.п.) на каждом прогоне `nx lint`. Правила `vuejs-accessibility/*` не пересекаются с правилами `vue/*` и с блоком изоляции модулей (`eslint-plugin-boundaries`).
- **Набор правил - `recommended` как есть.** Часть правил - severity `error`, что согласуется с будущим CI-гейтом линта. На текущем каркасе (демо-страница) набор не дал нарушений; послаблений не вводится.

Интеграция a11y в test-runner Storybook и axe в Vitest/Playwright намеренно НЕ вводятся - см. ниже.

## Почему не альтернативы

**axe в Vitest или `@axe-core/playwright`.** Полноценные a11y-тесты дают регрессионный гейт, но требуют либо настроенного Storybook test-runner, либо E2E-слоя, которых в проекте ещё нет, и идут вразрез со стратегией тестирования (массовые UI- и E2E-тесты осознанно отложены, см. [test-strategy.md](../spec/test-strategy.md)). Базового addon-а в Storybook достаточно для текущего этапа; axe в тестах вводится позже, когда появятся требования по доступности.

**Только Storybook addon, без линта.** Addon проверяет лишь то, что открыли в Storybook вручную; линт же покрывает все шаблоны на каждом прогоне и ловит проблему до коммита. Две точки дополняют друг друга: статический линт по шаблону + динамический axe по DOM.

**Только линт, без addon.** Статический анализ не видит вычисляемый DOM, контраст и фактические имена элементов после рендера. Addon закрывает этот класс проверок дёшево.

## Плюсы

- Очевидные a11y-дефекты ловятся в двух местах: статически в линте (все шаблоны, каждый прогон) и динамически в Storybook (реальный DOM).
- Встраивается в существующие инструменты - ни нового процесса, ни нового пакета-воркспейса.
- `recommended` с severity `error` согласован с будущим CI-гейтом линта.

## Минусы

- Две новые dev-зависимости (`@storybook/addon-a11y`, `eslint-plugin-vuejs-accessibility`).
- Статический линт не покрывает контраст и вычисляемый DOM; addon виден только для открытых вручную историй - полноценного регрессионного гейта по a11y нет (осознанно отложен).
- При росте числа компонентов часть правил `recommended` может потребовать точечной настройки.

## Последствия

- Новый `.vue`-шаблон проходит правила `vuejs-accessibility/*` на `nx lint`; нарушение уровня `error` валит линт.
- Story получает вкладку "Accessibility" в Storybook без дополнительной настройки.
- Апгрейд Storybook должен поднимать `@storybook/addon-a11y` вместе с остальным семейством (единая минорная версия).
