# ADR: Локальная конфигурация и приватные файлы

- Статус: Принято
- Дата: 2026-08-19
- Контекст: монорепозиторий DotnetVue3TemplateRu; часть файлов лежит вне git, их состав нигде не описан, а работа с ними разошлась по пяти документам

## Контекст

Вне git лежат четыре файла: `appsettings.Local.json` (личный оверрайд конфигурации API), `apps/frontend/web/.env.local` (переменные SPA при запуске вне Aspire), `CLAUDE.local.md` и `.claude/settings.local.json` (личные настройки агента). Заводить из них не нужно ни одного: `yarn dev` раздаёт адреса сам, и все четыре подключаются как необязательные.

Из-за этого возникали три проблемы.

1. **Состава нет.** Тема разорвана по пяти документам - `README.md`, `docs/guides/authentication.md`, `docs/backend/core/reference.md`, `docs/spec/arch-design/core/core-architecture.md` и `.claude/project-map.md`. Во всех пяти приватный файл описан как источник проблем: сказано, что забытый `appsettings.Local.json` уводит API мимо стека, но не сказано, как его завести и что в него положить.
2. **Формы нет.** Образцов `*.example` в репозитории не было ни одного, поэтому состав ключей приходилось выяснять из прозы README или из кода, читающего конфигурацию.
3. **`.gitignore` закрывал имена, а не классы.** Он перечислял приватные файлы поимённо, то есть ровно те, о которых вспомнили. Проверка `git check-ignore` показала дыру: голые `.env` и `.env.production` коммитились.

Ограничение: шаблон разворачивается в новый проект скриптом `scripts/init-from-template.sh`, и у проекта появятся свои приватные файлы. Конвенция должна закрывать и те файлы, которых в шаблоне ещё нет.

## Решение

**Приватный файл живёт рядом со своим потребителем; состав задан реестром; форму несёт коммитимый образец; попадание в git закрыто классами имён.**

- **Расположение.** Файл лежит там, где его ищет читающий его инструмент: `appsettings.Local.json` - в папке проекта API, `.env.local` - в корне Vite, файлы Claude Code - там, где их ждёт Claude Code. Настройка путей не требуется, потому что каждый инструмент находит свой файл по своему же соглашению.
- **Реестр.** [docs/guides/local-configuration.md](../guides/local-configuration.md) - единственное место, где перечислен состав: файл, читающий его код с номерами строк, содержимое и сценарий, в котором файл нужен. Остальные документы ссылаются на реестр вместо пересказа.
- **Образец.** Рядом с приватным файлом коммитится `<полное имя файла>.example`: он несёт форму и подсказку, где взять значения. Суффикс добавляется к полному имени, а не вставляется перед расширением, и для `appsettings.Local.json` это существенно - имя `appsettings.Local.example.json` попало бы под дефолтный glob `appsettings*.json` в `Microsoft.NET.Sdk.Web` и копировалось бы в `bin/`.
- **Классы имён в `.gitignore`.** Один блок со ссылкой на реестр закрывает `.env` и `.env.*` (кроме коммитимого `.env.development`), `*.private.*`, `secrets.json` и `*.secrets.json`, `appsettings.Local.json`, файлы Claude Code. Исключения `!.env.*.example` и `!*.private.*.example` пропускают образцы в коммит. Новый приватный файл, названный по конвенции, игнорируется сразу.

Настоящих секретов шаблон не содержит: подпись токенов асимметричная, симметричного ключа нет ([ADR-0023](0023-authentication-oidc.md)), а пароль PostgreSQL локального стека открыт намеренно - шаг настройки Logto читает из этой базы секрет служебного приложения. Значения из `.env.local` секретом быть не могут в принципе: Vite вкладывает их в бандл, который уезжает в браузер.

## Почему не альтернативы

**Единый приватный файл, из которого генерируются остальные.** Одно место для правки. Цена - слой генерации и обязательный шаг перед стартом: Vite читает `.env` только из своего `envDir`, а путь `.claude/settings.local.json` инструментом не настраивается вовсе, поэтому часть файлов пришлось бы генерировать скриптом. Появляется рассинхрон, когда правят сгенерированный файл, и обратный вопрос "почему мои правки затёрлись". Кроме того, файл, в который однажды ляжет настоящий пароль, стал бы файлом, который правят при каждой смене порта.

**Единый gitignored каталог `local/` в корне, по файлу на инструмент.** Один взгляд показывает все приватные файлы, форматы остаются родными. Цена - настройка путей у каждого потребителя: `envDir` в `vite.config.ts` утащил бы в тот же каталог и коммитимый `.env.development`, путь в `Program.cs` стал бы относительным к `ContentRootPath` и разъехался бы в Docker, а `.claude/settings.local.json` переехать не может вовсе - полного единого каталога всё равно не выходит.

**`dotnet user-secrets` вместо `appsettings.Local.json`.** Штатный механизм .NET, хранит файл в профиле пользователя, то есть физически вне репозитория. Цена - невидимость: файл не показывается в дереве проекта, правится через CLI, и положить рядом образец некуда. Для оверрайда адресов видимость важнее изоляции. Механизм остаётся доступной точкой расширения: `CreateBuilder` подключает `AddUserSecrets` в Development сам, и достаточно добавить `<UserSecretsId>` в `.csproj`, когда появится значение, которому нельзя лежать в папке проекта.

**Проверка staged-файлов в `pre-commit` вместо классов имён.** Поймала бы и случай `git add -f`, и файл, названный мимо конвенции. Цена - ещё один хук в поддержке и ложные срабатывания на образцах. Классы имён закрывают ту же дыру раньше, на уровне `.gitignore`, и без исполняемого кода; хук остаётся вариантом, если утечка случится вопреки паттернам.

## Плюсы

- Состав приватных файлов виден в одном документе, а не собирается из пяти; у каждого указано, какой код его читает и в каком сценарии он нужен.
- Форма файла задана коммитимым образцом: заведение сводится к `cp` и заполнению одного значения, без чтения кода.
- Дыра в `.gitignore` закрыта - проверено `git check-ignore` по 15 именам: `.env`, `.env.production`, `secrets.json`, `*.secrets.json` и `*.private.*` игнорируются, `.env.development` и все образцы коммитятся.
- Новый приватный файл в проекте из шаблона закрыт по имени, без правки `.gitignore`.

## Минусы

- Приватных файлов по-прежнему несколько, и по дереву они разнесены: единым становится реестр, а не расположение.
- Реестр пополняется руками; забытая строка не ломает сборку, поэтому расхождение обнаружится только при чтении.
- Исключения в `.gitignore` требуют порядка: `!.env.development` обязан стоять после `.env.*`, иначе коммитимый файл молча исчезнет из индекса.

## Последствия

- Документы, упоминающие приватные файлы, ссылаются на реестр вместо пересказа: `README.md` и его копия `template-overlay/README.md`, `docs/backend/core/reference.md`, `docs/guides/authentication.md`, `.claude/project-map.md`.
- Новый приватный файл заводится по конвенции: имя из закрытого класса, образец `<имя>.example` рядом, строка в реестре.
- Появление настоящего секрета - строки подключения к боевой базе, ключа внешнего сервиса - потребует отдельного решения о хранилище секретов среды развёртывания; локальная сторона закрыта этим ADR.
- Проверять закрытость файла нужно кодом возврата `git check-ignore -q`: вывод `-v` печатает совпавший паттерн и для исключений, поэтому по нему игнорируемый файл неотличим от коммитимого.
