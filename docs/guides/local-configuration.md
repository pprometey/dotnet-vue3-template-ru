# Гайд: локальная конфигурация

Какие файлы репозитория лежат вне git, что в каждый кладут и когда каждый нужен. Решение и обоснование - [ADR-0037](../adr/0037-local-configuration-and-secrets.md).

## Из коробки не нужен ни один

`yarn dev` поднимает весь стек и сам раздаёт адреса. Строку подключения к PostgreSQL и адрес провайдера идентичности API получает переменными окружения от Aspire, SPA получает от него же адрес API. Поэтому свежий клон запускается тремя командами из [README](../../README.md), и заводить локальные файлы не требуется.

Каждый файл ниже - оверрайд под конкретный сценарий: работа со своей базой вместо поднятой Aspire, запуск SPA отдельно от стека, личные настройки инструмента. Ненужный файл просто не создают: все они подключаются как необязательные, и без них запуск идёт штатно.

## Реестр

| Файл                                                           | Кто читает                                                 | Что кладут                                 | Образец                          |
| -------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------ | -------------------------------- |
| `apps/backend/DotnetVue3TemplateRu.Api/appsettings.Local.json` | биндер конфигурации .NET, подключение в `Program.cs:38-41` | секции `ConnectionStrings`, `Jwt`, `Cors`  | `appsettings.Local.json.example` |
| `apps/frontend/web/.env.local`                                 | dotenv внутри Vite                                         | `VITE_OIDC_CLIENT_ID`                      | `.env.local.example`             |
| `CLAUDE.local.md`                                              | Claude Code                                                | личные заметки агенту по этому репозиторию | нет                              |
| `.claude/settings.local.json`                                  | Claude Code                                                | личные разрешения инструментов             | нет                              |

## `appsettings.Local.json` - оверрайд конфигурации API

Нужен, когда API должен работать не с тем, что поднял Aspire: со своей базой PostgreSQL, со своим провайдером идентичности или с SPA на другом порту.

```bash
cd apps/backend/DotnetVue3TemplateRu.Api
cp appsettings.Local.json.example appsettings.Local.json
```

В скопированном файле оставляют только те секции, которые действительно нужно перебить, а остальные удаляют. Каждая оставленная секция перебивает значение, подставленное Aspire, даже если оно там было верным.

Файл подключается последним источником и только в Development (`Program.cs:38-41`), с `optional: true`. Полный порядок источников и список секций конфигурации - [docs/backend/core/reference.md](../backend/core/reference.md#конфигурация).

## `.env.local` - переменные SPA вне Aspire

Нужен ровно в одном сценарии: SPA запускают отдельно от стека, командой `yarn nx serve web`. Под `yarn dev` те же переменные подставляет AppHost, и они побеждают оба файла `.env`.

```bash
cd apps/frontend/web
cp .env.local.example .env.local
```

Заполнить нужно `VITE_OIDC_CLIENT_ID`: значение берут в консоли Logto на `http://localhost:3482`, в карточке приложения SPA. Пока оно пустое, вход выключен и приложение работает как без провайдера. Адреса API и провайдера уже лежат в коммитимом `.env.development` - в `.env.local` их повторяют, только если они расходятся.

## Файлы Claude Code

`CLAUDE.local.md` держит личные заметки агенту, а `.claude/settings.local.json` - личные разрешения инструментов поверх общего `.claude/settings.json`. Формат обоих задаёт Claude Code, поэтому образцов в репозитории нет. Правила и разрешения, общие для команды, идут в коммитимые `.claude/CLAUDE.md` и `.claude/settings.json`.

## Что здесь считается секретом

Настоящих секретов в шаблоне нет ни одного, и это следствие двух решений, а не случайность.

Подпись токенов асимметричная: API забирает открытые ключи по JWKS и симметричного ключа не хранит вовсе ([ADR-0023](../adr/0023-authentication-oidc.md)). Пароль PostgreSQL локального стека задан открыто в `aspire-apphost/apphost.mts` намеренно: шаг настройки Logto читает из этой базы секрет служебного приложения, а значение сгенерированного параметра из процесса AppHost прочитать нельзя. Подробнее - раздел "Порты" в [README](../../README.md).

Значения из `.env.local` секретом быть не могут по устройству Vite: он вкладывает их в собранный бандл, который целиком уезжает в браузер. `VITE_OIDC_CLIENT_ID` лежит вне git по другой причине. Идентификатор публичного клиента открыт по замыслу OAuth, а вкладку защищает PKCE; вне git он потому, что Logto выдаёт его при первой настройке и постоянного значения, которое можно было бы закоммитить, у него нет.

Секрет в полном смысле - строка подключения к боевой базе, ключ внешнего сервиса, пароль сервисной учётной записи. В шаблоне такого нет. Когда он появится в проекте, развёрнутом из шаблона, на машине разработчика ему место в `appsettings.Local.json`, а в среде развёртывания - в хранилище секретов этой среды.

## Как добавить новый приватный файл

`.gitignore` закрывает классы имён, а не отдельные файлы, поэтому новый приватный файл достаточно назвать по конвенции - правку `.gitignore` это не требует.

| Класс имён                       | Что закрывает                                                         |
| -------------------------------- | --------------------------------------------------------------------- |
| `.env`, `.env.*`                 | файл переменных окружения; исключение - коммитимый `.env.development` |
| `*.private.*`                    | приватная половина пары "публичный конфиг рядом с приватным"          |
| `secrets.json`, `*.secrets.json` | файл, целиком состоящий из секретов                                   |
| `appsettings.Local.json`         | личный оверрайд конфигурации .NET                                     |

Рядом с приватным файлом кладут образец: к полному имени добавляют `.example`, то есть `secrets.json` даёт `secrets.json.example`. Исключения `!.env.*.example` и `!*.private.*.example` уже стоят в `.gitignore`, поэтому образец коммитится сам. Образец несёт форму файла и подсказку, где взять значения, но не сами значения.

Новый файл добавляют строкой в реестр выше. Проверяют, что он закрыт:

```bash
git check-ignore -q путь/к/файлу && echo "вне git" || echo "попадёт в коммит"
```

Проверять нужно кодом возврата, а не выводом `git check-ignore -v`: тот печатает совпавший паттерн и для исключений вроде `!.env.development`, поэтому по его выводу игнорируемый файл неотличим от коммитимого.

## Ловушки

**`appsettings.Local.json` перебивает переменные Aspire.** Это его назначение и его же главная ловушка. Забытый файл со старым адресом уводит API мимо поднятого стека: запросы падают на чужой базе или отвечают 401, а сообщение об ошибке на настоящую причину не указывает. При странном поведении локального запуска этот файл проверяют первым.

**Файл конфигурации читается один раз, на старте.** Подключение идёт с `reloadOnChange: false` (`Program.cs:40`), поэтому правка на живом процессе ничего не меняет - API нужно перезапустить.

**`.env.local` действует и в прод-сборке.** Vite грузит его во всех режимах, в отличие от `.env.development`, который читается только в dev. Забытый файл с локальными адресами попадёт в `yarn nx build web` и уедет внутри собранного бандла.

**Развёртывание из шаблона переписывает и локальные файлы.** `scripts/init-from-template.sh` идёт заменой по всему дереву и приватные файлы не пропускает: лежащие на диске `appsettings.Local.json` и `.env.local` получают новое имя проекта и сдвинутые порты наравне с остальными файлами. Для оверрайда это обычно и нужно, но после прогона скрипта их стоит перечитать.
