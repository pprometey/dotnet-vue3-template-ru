# Guide: документация по Diátaxis

Проектная документация организуется по [Diátaxis](https://diataxis.fr): четыре квадранта по назначению, каждый - отдельный документ, квадранты не смешиваются в одном файле. Решение и обоснование - [ADR: Документация Diátaxis](../adr/0035-documentation-diataxis.md).

## Четыре квадранта

| Квадрант    | Назначение             | Читатель  | Отвечает на            |
| ----------- | ---------------------- | --------- | ---------------------- |
| tutorial    | learning-oriented      | новичок   | "проведи меня за руку" |
| how-to      | task-oriented          | практик   | "как сделать X"        |
| reference   | information-oriented   | практик   | "что здесь есть"       |
| explanation | understanding-oriented | изучающий | "почему так"           |

- Учебник (tutorial) - урок на живой системе: от начала до видимого результата, минимум теории, каждый шаг гарантированно работает.
- Практические инструкции (how-to) - рецепт под конкретную задачу: последовательность шагов, без объяснений "почему".
- Справочник (reference) - сухое описание машинерии: структура, компоненты, сторы, контракты, параметры. Без сценариев и мотивации.
- Пояснения (explanation) - почему так устроено: границы решений, компромиссы, связи. Без пошаговых инструкций.

## Критерий выбора квадранта

- Читатель учится с нуля и хочет попробовать -> tutorial.
- У читателя конкретная задача и он знает, чего хочет -> how-to.
- Читателю нужен факт об устройстве (имя компонента, поле стора, роут) -> reference.
- Читатель хочет понять замысел и границы -> explanation.

Если материал тянет в два квадранта - это два документа. Смешанный документ не служит ни одному читателю.

## Раскладка в репозитории

- Документация реализации модуля - в per-module папке `docs/<area>/<module>/` (`docs/backend/<module>/` для backend-модулей, `docs/frontend/<page>/` для разделов SPA):
  - `README.md` - индекс: что за модуль и когда идти к какому из четырёх документов;
  - `tutorial.md`, `how-to.md`, `reference.md`, `explanation.md`.
- Кросс-проектные рецепты (не привязанные к одному модулю) - в `docs/guides/` (это квадрант how-to уровня проекта).
- Решения уровня проекта - в `docs/adr/` (decision records, форма explanation).

Первый носитель формы - [docs/backend/core/](../backend/core/README.md).

## Как добавить документацию нового модуля

1. Создать папку `docs/<area>/<module>/` и в ней пять файлов: `README.md` + четыре квадранта.
2. В `README.md` - одна строка на квадрант: что внутри и когда сюда идти; ссылки на кросс-проектные ADR/гайды.
3. Наполнять по назначению квадранта; общие принципы не дублировать - ссылаться на ADR и `docs/guides/`.
4. Добавить указатель на папку в Project Map (`.claude/project-map.md`).

## Голос документации

Писать обезличенно, от лица проекта, без обращения к читателю на "вы" и без следов диалога. Требования формулировать как факты проекта.
