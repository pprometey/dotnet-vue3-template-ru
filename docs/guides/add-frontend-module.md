# Гайд: добавить раздел фронтенда

Как завести новый раздел интерфейса и разложить его по уровням. Почему так - [ADR-0028](../adr/0028-frontend-structure.md); модель приложения - [ADR-0027](../adr/0027-frontend-spa.md).

## Уровни и направление импорта

Импорт идёт только "вниз". Каждый уровень видит то, что ниже, и не видит соседа своего уровня.

| Уровень     | Где                                         | Что там                                                                 |
| ----------- | ------------------------------------------- | ----------------------------------------------------------------------- |
| app         | `src/main.ts`, `src/App.vue`, `src/router/` | composition root и склейка веток маршрутов                              |
| core        | `src/core/*`                                | каркас страницы, i18n, OIDC-клиент, сервисы конфигурации и сессии, тема |
| page        | `src/pages/<page>/`                         | раздел = ветка маршрутов: свой `routes.ts`, экраны, стор раздела        |
| feature     | `src/pages/<page>/features/<feature>/`      | вертикальный срез внутри раздела                                        |
| page-shared | `src/pages/<page>/shared/*`                 | листья, общие для фич одного раздела                                    |

Страница не импортирует страницу-сестру, фича не импортирует фичу-сестру. Интеграция двух фич - на уровне страницы (она владеет связывающим их состоянием) или через `page-shared`. Интеграция двух разделов - через `core` или через маршрут.

## Шаги

**1. Завести папку раздела.**

```text
src/pages/reports/
  routes.ts
  ReportsPage.vue
  i18n/{ru,en,kk}.json
  features/
    report-filters/
      ReportFilters.vue
      index.ts
```

**2. Описать маршруты.** Компонент страницы грузится лениво - это и есть разбиение бандла по маршрутам.

```ts
import type { RouteRecordRaw } from "vue-router";

export const reportsRoutes: RouteRecordRaw[] = [
  {
    path: "/reports",
    name: "reports",
    component: () => import("./ReportsPage.vue"),
  },
];
```

**3. Подключить ветку в роутер** (`src/router/index.ts`):

```ts
import { reportsRoutes } from "@pages/reports/routes";

const routes: RouteRecordRaw[] = [
  { path: "/", redirect: { name: "notes" } },
  ...notesRoutes,
  ...reportsRoutes,
  ...authRoutes,
  /* ... */
];
```

**4. Положить переводы** в `i18n/<locale>.json` рядом с кодом. Они подхватываются глобом автоматически - регистрировать словарь нигде не нужно. Namespace верхнего уровня совпадает с именем раздела, чтобы ключи разделов не сталкивались.

**5. Написать фичи.** Каждая отдаёт наружу свой публичный вход через `index.ts`; приватные подкомпоненты лежат рядом с родителем.

Настраивать границы под новый раздел не нужно: паттерны в `eslint.config.mjs` обобщённые (`pages/*`, `pages/*/features/*`), новый раздел подпадает под них сам.

## Данные

Серверное состояние - только через сгенерированные Orval composables ([ADR-0029](../adr/0029-tan-stack-query.md)). HTTP-код руками не пишется.

```ts
const { data, isPending } = useGetApiV1ReportsId(computed(() => id.value));
```

UI-состояние (открыт ли модал, текущий шаг) остаётся в `ref`/`reactive` без библиотек. Стор раздела заводится, когда состояние переживает переход между экранами раздела или связывает две фичи.

## Проверка

```bash
yarn nx run web:lint     # границы уровней
yarn nx run web:build
yarn nx run web:test
```

Зелёный линт сам по себе ещё не значит, что границы проверяются. Добавьте в фичу импорт соседней фичи, запустите `lint` и убедитесь, что он падает с `boundaries/element-types`; потом откатите импорт.

Проба нужна из-за того, как устроен плагин. Уровень файла он определяет по совпадению пути с шаблонами из `boundaries/elements`; файл, не совпавший ни с одним шаблоном, остаётся без уровня, и правило `element-types` его не рассматривает. Поэтому опечатка в шаблоне пути не даёт ни ошибки, ни предупреждения: новый раздел просто выпадает из проверки, а прогон выглядит точно так же, как при работающем правиле.

## Ловушки

**Барель и ленивый импорт тоже проверяются.** В `eslint.config.mjs` стоит `dependency-nodes: ["import", "export", "dynamic-import"]`. Без этой настройки правило смотрело бы только на `import`, а барель фичи состоит из `export ... from`, и страницы грузятся через `import()` - обе дыры остались бы незакрытыми.

**Импорты между уровнями - по псевдонимам** (`@core/*`, `@pages/*`), внутри своей папки - относительные. Псевдоним - только путь: граф зависимостей линт строит по фактическому расположению файла.

**Общее поднимается по факту второго потребителя**, а не заранее. Пока фича одна, `page-shared` заводить не нужно.
