# ADR: TanStack Query для управления серверным состоянием

- Статус: Принято
- Дата: 2026-08-11
- Контекст: монорепозиторий DotnetVue3TemplateRu, `libs/frontend/api-client`, `apps/frontend/web`

## Контекст

Большая часть состояния в приложении - это **серверное состояние**: данные,
которые живут на сервере, кэшируются на клиенте и должны актуализироваться.
Примеры: список записей, ход выполнения текущей операции, сводный экран. Это
принципиально отличается от **UI-состояния** (открыт ли модал, введённый текст
в форме), которым управляет обычный реактивный стек Vue.

Требования к работе с серверным состоянием видны прямо из типичных сценариев:

- Экран хода выполнения показывает, что уже готово, а что нет. Пользователь
  держит его открытым и ждёт; данные обязаны обновляться сами при возврате на
  вкладку, а не по кнопке "обновить".
- Сводный экран одновременно рисуют несколько блоков. Запрос к одному ресурсу
  должен уходить один раз, а не по разу на блок.
- После сохранения карточки список обязан перерисоваться сам - иначе пользователь
  увидит в нём старое состояние записи, которую только что изменил.
- Уход с экрана обязан отменять запрос, иначе ответ приходит в размонтированный
  компонент.

## Решение

Выбрана библиотека **TanStack Query v5** (`@tanstack/vue-query@5.62.8`) в связке
с Orval-генерацией: Orval читает OpenAPI-схему бэкенда и генерирует готовые
Vue-composables (`useQuery` / `useMutation`) поверх TanStack Query.

Три компонента решения:

**1. `@tanstack/vue-query`** - ядро: `QueryClient` (кэш), `useQuery` (чтение
данных), `useMutation` (запись). Управляет жизненным циклом запросов, повторными
попытками, фоновым обновлением.

**2. Orval** с `client: "vue-query"` - кодогенерация. По OpenAPI-схеме генерирует
типизированные composables в `libs/frontend/api-client/src/generated/`. Разработчик
не пишет `useQuery` вручную - Orval делает это из контракта API.

**3. Один `QueryClient` на приложение.** `main.ts` подключает `VueQueryPlugin`
один раз при старте (ADR-0027). Приложение на странице одно, изолировать кэш не
от кого, а общий клиент - это ровно то, что даёт дедупликацию и инвалидацию
между разными экранами: сохранив карточку на одном экране, можно инвалидировать
список на другом.

## Что такое TanStack Query

TanStack Query - библиотека для управления серверным состоянием в клиентских
приложениях. Центральный объект - `QueryClient`, который хранит кэш запросов.

**Ключевые понятия:**

- **Query key** - уникальный идентификатор кэш-записи. Пример: `["notes", noteId]`.
  Одинаковый ключ = один кэш-слот; если два компонента делают `useQuery` с одним
  ключом, HTTP-запрос уходит один раз.
- **`useQuery`** - подписывается на кэш-запись, автоматически выполняет fetch и
  обновляет реактивные `data`, `isPending`, `isError`.
- **`useMutation`** - для операций записи (POST/PUT/DELETE). После успеха вызывается
  `queryClient.invalidateQueries(...)` чтобы принудительно обновить связанные данные.
- **stale-while-revalidate** - возвращает кэшированные данные мгновенно, параллельно
  делает фоновый запрос. Пользователь видит данные без мигания "загрузка".

## Почему не альтернативы

**Pinia для всего (actions + state).**
Pinia - отличный инструмент для UI-состояния, но серверное состояние требует
ручного кода: флаги `isLoading` / `isError`, дедупликация запросов, инвалидация
после мутаций, повторные попытки при ошибках. Это десятки строк шаблонного кода
на каждый ресурс. TanStack Query делает это из коробки.

**Ручной axios + composables.**
Аналогично Pinia: весь boilerplate пишется вручную. Легко забыть про отмену
запроса, дедупликацию или инвалидацию. Хрупко при масштабировании.

**Apollo Client.**
Ориентирован на GraphQL. API бэкенда - REST/HTTP, Apollo здесь неприменим.

**SWR.**
Нет официальной поддержки Vue.

**TanStack Query без Orval (вручную).**
Composables можно писать вручную, но тогда они могут разойтись с контрактом API.
Orval гарантирует актуальность: изменился эндпоинт в C# - после `nx run
api-client:generate` composable обновляется автоматически.

## Ключевые возможности, используемые в проекте

**Интеграция с Orval** (см. [ADR: Автогенерация API-клиента](0026-auto-generate-api.md))**.**
Из OpenAPI JSON (`apps/backend/DotnetVue3TemplateRu.Api/openapi/DotnetVue3TemplateRu.Api.json`)
Orval генерирует файлы в `libs/frontend/api-client/src/generated/<tag>/`.
Каждый файл содержит чистую HTTP-функцию (`postApiV1Notes`, `getApiV1NotesId`) и
wrapping composable (`usePostApiV1Notes`, `useGetApiV1NotesId`). Разработчик
импортирует только composable - HTTP-код не пишется вручную.

**Общий кэш на всё приложение.**
Единственный `QueryClient` означает, что кэш переживает переход между
маршрутами: возврат на сводный экран показывает данные мгновенно, а
фоновый запрос обновляет их тихо.

**stale-while-revalidate.**
Данные отображаются мгновенно из кэша, фоновый запрос обновляет их тихо.
`staleTime` по умолчанию - 0ms (всегда актуальные данные). Можно задать
на уровне вызова `useQuery` для длинных кэшей.

**Дедупликация запросов.**
Если два компонента вызывают `useGetApiV1NotesId({ id })` с одинаковым id
одновременно, уходит один HTTP-запрос. Оба компонента получают одни данные.

**Отмена запросов.**
Кастомный axios-мутатор (`libs/frontend/api-client/src/mutator/custom-axios.ts`)
добавляет `.cancel()` к каждому запросу. TanStack Query вызывает отмену при
демонтировании компонента, предотвращая race conditions.

## Как использовать

**Чтение данных (`useQuery`):**

```ts
import { useGetApiV1NotesId } from "@dotnet-vue3-template-ru/api-client";

const noteId = ref("some-uuid");

const { data, isPending, isError } = useGetApiV1NotesId(
  computed(() => ({ id: noteId.value })),
);
// data      - Ref<NoteResponse | undefined>
// isPending - Ref<boolean>, true пока запрос не вернул данные
// isError   - Ref<boolean>, true при ошибке
```

Реактивный параметр: если `noteId.value` изменится, запрос выполнится заново
автоматически.

**Запись данных (`useMutation` + инвалидация кэша):**

```ts
import {
  usePostApiV1Notes,
  getGetApiV1NotesIdQueryKey,
} from "@dotnet-vue3-template-ru/api-client";
import { useQueryClient } from "@tanstack/vue-query";

const queryClient = useQueryClient();

const { mutate, isPending } = usePostApiV1Notes({
  mutation: {
    onSuccess: (newNote) => {
      queryClient.invalidateQueries({
        queryKey: getGetApiV1NotesIdQueryKey({ id: newNote.id }),
      });
    },
  },
});

mutate({ data: { texts: { ru: "Новая заметка" } } });
```

## Плюсы выбранного подхода

- Нет boilerplate: `useQuery` / `useMutation` заменяют десятки строк ручного кода.
- Автогенерация Orval: composables всегда соответствуют актуальному API-контракту.
- Типобезопасность: типы из OpenAPI, ошибки компиляции при несоответствии.
- Кэш общий на приложение: данные, загруженные одним экраном, мгновенно доступны другому.
- Автоматическое обновление данных при возврате на вкладку / восстановлении сети.
- Дедупликация и отмена запросов из коробки.

## Минусы и ограничения

- Кривая обучения: нужно понять query keys, stale time, инвалидацию кэша.
  Неправильный ключ - несинхронизированные данные или лишние запросы.
- Для простых one-off запросов (например, форма логина) `useMutation` выглядит
  избыточно против прямого `axios.post`.
- Кэш - это состояние: при сложных сценариях нужно аккуратно управлять
  инвалидацией, иначе пользователь видит устаревшие данные.
- Зависимость от Orval-пайплайна: если бэкенд не собирается (`dotnet build`),
  генерация не работает и composables устаревают.

## Последствия

- Для каждого нового API-эндпоинта composable генерируется автоматически командой
  `nx run api-client:generate`. Ручное написание HTTP-кода в компонентах не нужно.
- Серверное состояние (списки, детали записей, справочники) управляется через
  TanStack Query. UI-состояние (открыт ли дропдаун, текущий шаг визарда)
  остаётся в `ref`/`reactive` без библиотек.
- `QueryClient` создаётся один раз в `main.ts`; новые разделы подключаются к нему автоматически.
