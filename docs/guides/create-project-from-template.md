# Развернуть новый проект из шаблона

Шаблон - это обычный работающий репозиторий: он собирается, проходит тесты и поднимается через `yarn dev`. Новый проект получается копией шаблона, по которой один раз прогнали `scripts/init-from-template.sh`.

## Почему не плейсхолдеры

Обычный шаблон хранит в исходниках метки вроде `{{ project_name }}`, которые подставляются при генерации. Здесь так не сделано намеренно: как только имя проекта в `.csproj` заменяется меткой, репозиторий перестаёт компилироваться, и проверить работоспособность шаблона становится нечем. Шаблон, который нельзя собрать и прогнать тестами, незаметно ломается - и обнаруживается это уже в новом проекте.

Поэтому имя шаблона (`DotnetVue3TemplateRu`) - настоящее имя настоящего проекта, а скрипт делает переименование, а не подстановку.

## Порядок действий

```bash
git clone https://github.com/pprometey/dotnet-vue3-template-ru.git my-app
cd my-app
rm -rf .git

./scripts/init-from-template.sh --name MyApp --port-offset 100

yarn install
dotnet build MyApp.slnx
git init && git add -A && git commit -m "Первый коммит из шаблона"
```

Коммит делается после успешной сборки: иначе в истории останется состояние с наполовину переименованными проектами, к которому потом придётся возвращаться при разборе.

`yarn install` здесь обязателен и обязательно без `--immutable`. Скрипт переименовал workspace-пакеты внутри `yarn.lock` (`@dotnet-vue3-template-ru/api-client` стал `@my-app/api-client`), а записи в lock-файле отсортированы по имени - значит, после переименования yarn переупорядочит их сам. С `--immutable` он вместо этого откажется работать с сообщением "The lockfile would have been modified". Переупорядоченный `yarn.lock` входит в первый коммит; дальше, уже в CI, `--immutable` проходит штатно.

## Аргументы скрипта

| Аргумент        | Обязателен | Что делает                                                                                        |
| --------------- | ---------- | ------------------------------------------------------------------------------------------------- |
| `--name`        | да         | PascalCase-имя проекта, `^[A-Z][A-Za-z0-9]*$`. Даёт namespace, имена проектов, каталогов и файлов |
| `--port-offset` | да         | Целое 0..40000. Прибавляется к каждому внешнему порту                                             |
| `--kebab`       | нет        | kebab-форма, если автоматический вывод не устраивает                                              |
| `--keep-script` | нет        | Не удалять скрипт и не накладывать overlay. Только для сопровождения самого шаблона               |

Точек в имени быть не может: из него выводятся имена каталогов и npm-scope, а `Acme.Crm` дал бы каталог с точкой и невалидный scope. Модули внутри проекта именуются иначе - там точки как раз есть (`MyApp.Billing.Domain`), их заводит `scripts/add-new-module.sh`.

## Три формы имени

Скрипт выводит из `--name` три формы и заменяет каждую своим набором мест:

| Форма      | Пример   | Куда попадает                                                                                                                                            |
| ---------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PascalCase | `MyApp`  | namespace и типы в C#, имена `.csproj` и каталогов проектов, `.slnx`, `UseMyAppDurability`, заголовок вкладки, i18n-словари, `Dockerfile`                |
| kebab-case | `my-app` | имена npm-пакетов, алиас `@my-app/api-client`, ключ строки подключения `my-app-db`, том `my-app-pgdata`, домен `api.my-app.local`, имя `.code-workspace` |
| camelCase  | `myApp`  | ключ конфигурации в `libs/frontend/api-client/orval.config.ts`                                                                                           |

`MyApp` даёт `my-app` по тому же правилу, что и `scripts/add-new-module.sh`: дефис ставится там, где за строчной буквой или цифрой идёт заглавная. Если результат не устраивает, задайте `--kebab` явно.

## Как выбрать смещение портов

Смещение обязательно и не имеет значения по умолчанию, потому что порты в этом стеке закреплены жёстко: их знают друг про друга CORS-политика API, список адресов возврата у Logto и настройки Vite. Два проекта из этого шаблона с одинаковыми портами одновременно не поднимутся, а конфликт проявится не сразу и невнятно - например, вход будет уводить в чужое приложение.

Держите таблицу занятых смещений. Шаблон занимает нулевое, поэтому первому проекту дайте 100, второму 200 и так далее.

| Порт при смещении 0 | Назначение                      |
| ------------------- | ------------------------------- |
| 5173                | SPA (Vite)                      |
| 3481                | Logto, выдача токенов           |
| 3482                | Logto, консоль                  |
| 1425                | Mailpit, приём почты            |
| 8425                | Mailpit, веб-интерфейс          |
| 5249 / 7324         | API, http / https               |
| 18181 / 16197       | Aspire, дашборд https / http    |
| 21316 / 22120       | Aspire, OTLP и resource service |
| 6006                | Storybook                       |

Внутренние порты контейнеров скрипт не трогает: 3001 и 3002 у Logto, 1025 и 8025 у Mailpit, 8080 в `Dockerfile`, 5432 у PostgreSQL. Они живут внутри сети Docker и между проектами не конфликтуют.

## Что скрипт делает по шагам

1. **Проверяет аргументы** и отказывается работать, если в корне нет `DotnetVue3TemplateRu.slnx` - значит, каталог не является копией шаблона.
2. **Переименовывает каталоги и файлы**, в именах которых есть имя шаблона: 7 каталогов проектов, `.slnx`, `.code-workspace`, пять `.csproj`, `openapi/*.Api.json`, `*DbContext.cs`, `*DbContextFactory.cs`, `*DbContextModelSnapshot.cs`, `*ApiFactory.cs`. Обход идёт от листьев к корню, поэтому переименование вложенного пути не ломает ещё не пройденный родительский.
3. **Заменяет три формы имени** в содержимом всех текстовых файлов. Бинарных файлов в репозитории нет, так что замена безопасна везде.
4. **Сдвигает порты** - во всех файлах, кроме `yarn.lock`. Это исключение принципиально: числа вроде `5173` встречаются внутри контрольных сумм пакетов, и замена там сломала бы lock-файл. Сама замена двухфазная, через временные метки, иначе сдвинутый порт мог бы совпасть с ещё не обработанным исходным и попасть под замену второй раз.
5. **Накладывает `template-overlay/`** - каталог с файлами, которые в проекте выглядят иначе, чем в шаблоне (сейчас это `README.md`), и удаляет его.
6. **Удаляет себя.**

## Проверить результат

```bash
grep -rI "DotnetVue3TemplateRu\|dotnet-vue3-template-ru" . --exclude-dir=node_modules --exclude-dir=.git
dotnet build MyApp.slnx
yarn install
yarn nx run architecture-tests:test
yarn nx run web:test
yarn nx run integration-tests:test
yarn dev
```

Первая команда должна не найти ничего. Последняя - поднять стек на сдвинутых портах; зайдите в SPA, войдите через Logto и создайте заметку. Если сквозной путь работает, проект готов к разработке.
